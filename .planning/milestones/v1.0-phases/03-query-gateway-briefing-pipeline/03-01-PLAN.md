<objective>
Scaffold the `@argon/gateway` service using Hono on Node.js (`@hono/node-server`), implement fail-closed Bearer token authentication middleware, expose the public `GET /health` endpoint, and implement authenticated query endpoints (`POST /api/v1/:workspaceId/query/:queryName`) for the 8 named FalkorDB queries with Zod parameter validation, `GRAPH.RO_QUERY` execution, and strict 5-second timeout handling returning HTTP 503.

Purpose: Establishes the secure, high-performance HTTP gateway in `apps/gateway` that bridges client applications and agents to FalkorDB over Direct VPC egress without exposing raw Cypher endpoints.
Output: Working `@argon/gateway` application, auth middleware, health endpoint, query routing with timeout enforcement, and automated Vitest test suites.
</objective>

<threat_model>
### ASVS Level 1 Controls & Threat Mitigations

| Threat ID | Threat Description | ASVS Control | Mitigation in this Plan |
|---|---|---|---|
| **T-03-01** | Authentication Bypass / Missing Secret: Unauthenticated requests access private graph queries if token check is missing or improperly configured. | **ASVS V2.1.1** (Verify access control on protected resources) | `bearerAuthMiddleware` fails closed: returns HTTP 500 `AUTH_CONFIG_ERROR` if `GATEWAY_SECRET` is unset/empty, returns HTTP 401 `UNAUTHORIZED` if `Authorization` header is missing or does not match `Bearer <GATEWAY_SECRET>`. `/health` is explicitly public per D-02. |
| **T-03-02** | Cypher Injection / Arbitrary Query Execution: Attackers submit crafted Cypher strings to execute data manipulation or schema destruction. | **ASVS V5.3.4** (Parameterized queries and strict input typing) | No generic `/query` endpoint accepting arbitrary Cypher strings. Endpoints strictly whitelist the 8 named queries (`/query/:queryName`), validate all parameters against Zod schemas in `@argon/graph`, and execute exclusively through `GRAPH.RO_QUERY` per D-01 and PRD §11.1. |
| **T-03-05** | Denial of Service via Long-Running Queries / Resource Starvation: Unbounded graph traversals consume server CPU and memory, hanging gateway connections. | **ASVS V11.1.4** (Verify resource limits and connection timeouts) | Every query execution is bounded by a strict 5000ms timeout (`Promise.race` with timer). On timeout or connection drop, the handler returns HTTP 503 with structured code `FALKORDB_TIMEOUT` or `FALKORDB_UNREACHABLE` per D-03. |
| **T-03-13** | Information Disclosure via Error Stack Traces: Internal database connection strings or Redis stack traces leaked to clients. | **ASVS V7.1.1** (Sanitize error responses) | Gateway error middleware catches unhandled exceptions and maps them to sanitized JSON error envelopes with structured error codes, preventing internal connection strings or stack traces from escaping. |
</threat_model>

     - `resolveScope`: `ResolveScopeParamsSchema`
     - `blastRadius`: `BlastRadiusParamsSchema`
     - `riskRanking`: `RiskRankingParamsSchema`

     - `precedentSearch`: `PrecedentSearchParamsSchema`
     - `pathBetween`: `PathBetweenParamsSchema`
     - `componentOverview`: `ComponentOverviewParamsSchema`

   - Create a timeout promise rejecting with an `Error('QUERY_TIMEOUT')` after 5000ms.
