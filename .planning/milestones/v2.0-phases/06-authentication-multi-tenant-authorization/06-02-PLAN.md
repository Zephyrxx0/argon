### ASVS Level 1 Controls & Threat Mitigations

| Threat ID | Threat Description | Severity | ASVS Category | Mitigation Strategy |
|---|---|---|---|---|
| **T-06-04** | Multi-tenant graph data leakage / Cypher injection in schema traversal | High | V5 Injection | Use strictly parameterized openCypher queries (`client.roQuery(ws, cypher, { workspaceId, userId })`) with zero string interpolation or query concatenation (D-09, D-11). |
| **T-06-05** | JWT token tampering / algorithm confusion (`alg: none` or RS256/HS256 mismatch) | High | V3 Session Management | In `jwtAuthMiddleware`, use `hono/jwt` with explicit `'HS256'` parameter and reject tokens that fail cryptographic signature verification with `BETTER_AUTH_SECRET` (D-05, D-08). |
| **T-06-06** | Broken Object Level Authorization (BOLA) / unauthorized tenant workspace access | High | V4 Access Control | Execute pre-query FalkorDB guard before delegating to named queries; return `403 Forbidden` with `{ error: 'Workspace access denied', code: 'FORBIDDEN' }` if `!access.allowed`, and `404 Not Found` if workspace does not exist (D-11, D-12). |
| **T-06-08** | PII leakage in graph database | High | V8 Data Protection | Ensure `(:User)` nodes in FalkorDB never store user email addresses; only store `id`, `github_id`, `login`, `avatar_url`, and `created_at` (D-10). |
</threat_model>

<title>Extend FalkorDB openCypher schema with :User and [:ACCESSES] and implement checkWorkspaceAccess</title>

<action>
1. Update `packages/graph/src/schema/schema.cypher`:
   - Document `(:User)` node schema:
     - `id: STRING` (Better Auth userId / guestId)
     - `github_id: STRING` (GitHub numeric ID as string, null for guests)
     - `login: STRING` (GitHub handle or guest handle)
     - `avatar_url: STRING` (Avatar URL or fallback)
     - `created_at: INTEGER` (epoch ms)
     - Explicitly note: raw emails MUST NOT be stored in FalkorDB per D-10.
   - Document `(:Workspace)` node schema:
     - `id: STRING`
     - `is_public: BOOLEAN` (true for showcase repos per D-09)
     - `name: STRING`
     - `repo_url: STRING`
   - Document `(:Organization)` node schema:
     - `id: STRING`
     - `name: STRING`
     - `created_at: INTEGER`
   - Document relationships:
     - `(User)-[:ACCESSES { role: 'owner' | 'member' | 'viewer' }]->(Workspace)`
     - `(User)-[:MEMBER_OF { role: 'admin' | 'member' }]->(Organization)`
     - `(Organization)-[:OWNS]->(Workspace)`
   - Add range indexes:
     - `CREATE INDEX FOR (u:User) ON (u.id);`
     - `CREATE INDEX FOR (w:Workspace) ON (w.id);`
     - `CREATE INDEX FOR (o:Organization) ON (o.id);`

2. Update `packages/graph/src/schema/init.ts`:
   - Add range index creation for `(u:User).id`, `(w:Workspace).id`, and `(o:Organization).id`.
   - Add unique constraints for `{ label: 'User', prop: 'id' }`, `{ label: 'Workspace', prop: 'id' }`, `{ label: 'Organization', prop: 'id' }`.
   - Ensure `initWorkspaceGraph` executes `MERGE (w:Workspace {id: $workspaceId}) ON CREATE SET w.is_public = (CASE WHEN $workspaceId = 'ember-adr-showcase' OR $workspaceId = 'synthetic-demo' OR $workspaceId = 'argon-dogfood' THEN true ELSE false END)` to prevent showcase lockouts.

3. Create `packages/graph/src/queries/auth.ts`:
   - Implement `checkWorkspaceAccess(client: ArgonGraphClient, workspaceId: string, userId: string): Promise<{ exists: boolean; allowed: boolean }>`:
     - Use parameterized FalkorDB openCypher query with `OPTIONAL MATCH`:
       ```cypher
       MATCH (w:Workspace {id: $workspaceId})
       OPTIONAL MATCH (u:User {id: $userId})-[r:ACCESSES]->(w)
       RETURN count(w) > 0 AS exists,
              (w.is_public = true OR r IS NOT NULL) AS allowed;
       ```
     - DO NOT use unsupported nested `WHERE EXISTS { MATCH ... }` subqueries!
     - Return `{ exists: Boolean(row?.exists), allowed: Boolean(row?.allowed) }`.
   - Implement `setUserWorkspaceAccess(client: ArgonGraphClient, params: { workspaceId: string, userId: string, role: 'owner' | 'member' | 'viewer', isPublic?: boolean }): Promise<void>`:
     - Creates/merges `(:Workspace {id: $workspaceId})`, `(:User {id: $userId})`, and `[:ACCESSES { role: $role }]`.

4. Export `checkWorkspaceAccess` and `setUserWorkspaceAccess` from `packages/graph/src/queries/index.ts` and `packages/graph/src/index.ts`.

5. Create `packages/graph/test/schema/tenant-schema.test.ts` (and ensure vitest finds it):
   - Test `checkWorkspaceAccess` returns `{ exists: false, allowed: false }` for non-existent workspace.
   - Test `checkWorkspaceAccess` returns `{ exists: true, allowed: true }` for public workspace (`is_public = true`) regardless of userId.
   - Test `checkWorkspaceAccess` returns `{ exists: true, allowed: false }` for private workspace (`is_public = false`) without `[:ACCESSES]` edge.
   - Test `checkWorkspaceAccess` returns `{ exists: true, allowed: true }` for private workspace with `[:ACCESSES]` edge.
   - Verify `(:User)` nodes created have no email property.
</action>

     ```typescript
     export interface JwtAuthUser {

       isAnonymous: boolean;

     }
     ```

2. Create `apps/gateway/src/middleware/jwt.ts`:
   - Import `verify` from `hono/jwt`.
   - Define `jwtAuthMiddleware(secretOverride?: string): MiddlewareHandler`:
     - Reads `secret = secretOverride ?? process.env.BETTER_AUTH_SECRET ?? process.env.GATEWAY_SECRET`.
     - If secret is missing, returns 500 with `AUTH_CONFIG_ERROR`.
     - Extracts `Authorization: Bearer <token>`. If missing, returns 401 with `UNAUTHORIZED`.
     - Backward compatibility check: if `token === secret`, sets `c.set('user', { userId: 'admin', isAnonymous: false })` and proceeds to `next()` (preserves existing internal and test harness traffic).
     - Verifies token using `await verify(token, secret, 'HS256')`.
     - Extracts `userId = String(payload.userId ?? payload.sub ?? '')` and `isAnonymous = Boolean(payload.isAnonymous)`.
     - If `!userId`, returns 401 with `UNAUTHORIZED`.
     - Sets `c.set('user', { userId, isAnonymous, ...payload })` and calls `next()`.
     - Catches verification errors and returns 401 with `{ error: 'Invalid Bearer token: ...', code: 'UNAUTHORIZED' }`.

3. Create `apps/gateway/test/middleware/jwt-auth.test.ts`:
   - Test valid HS256 token signed with `BETTER_AUTH_SECRET` passes and populates `c.get('user')`.
   - Test anonymous token with `isAnonymous: true` passes and sets `user.isAnonymous === true`.
   - Test static secret fallback matches and sets admin user.
   - Test missing Authorization header returns 401.
   - Test malformed or invalid signature returns 401.
   - Test expired token returns 401.

     - Reads `workspaceId = c.req.param('workspaceId')`.
     - If `!workspaceId`, proceeds to `next()`.
     - Reads `user = c.get('user') as JwtAuthUser | undefined`.

     - If `!access.allowed`: returns 403 Forbidden with `{ error: 'Workspace access denied', code: 'FORBIDDEN' }` (D-11, D-12).
     - If `access.allowed`: proceeds to `await next()`.
     - Catches errors and returns 500 with `INTERNAL_ERROR`.
