# Plan 08-03: Real-Time SSE Stream, Cytoscape Neon Sync Pulse & UI Invalidation

> Implement workspace-scoped Server-Sent Events (SSE) in `apps/gateway`, real-time client sync listeners, Cytoscape canvas neon ring pulse animations, HUD status badges, and active briefing staleness alerts (SYNC-03).

---

## Objective

Deliver the real-time feedback loop for Phase 8: stream sync completion events from `apps/gateway` to `apps/web` over authenticated Server-Sent Events (SSE), dynamically render neon ripple pulses on updated nodes and dimmed dashed borders on superseded ADRs in the Cytoscape canvas, show a temporary monospace HUD status badge, and alert users when an active briefing's citations have been updated (SYNC-03).

---

## Must Haves

<must_haves>
### Truths
- `GET /api/v1/workspaces/:workspaceId/events` establishes a standard HTTP `text/event-stream` with 15-second heartbeat keepalive.
- Unauthenticated requests or unauthorized access to private workspaces return HTTP `401 Unauthorized` or `403 Forbidden`.
- Completing an incremental sync broadcasts `sync:complete` containing `{ workspaceId, trigger, updated: { commits, files, decisions }, superseded }` to clients connected to that specific workspace.
- `apps/web` connects to the SSE stream via `useWorkspaceEvents()` and automatically reconnects with exponential backoff on disconnects.
- Receiving `sync:complete` merges new elements via `cy.add()`, animates an expanding cyan/amber ring pulse on updated nodes, and styles superseded ADRs with dimmed dashed borders.
- `HUDControls` renders a monospace status badge (`LIVE SYNC • +N commits, N ADR superseded`) for 5 seconds before fading out.
- If the open `BriefingView` cited any updated files or superseded decisions, a non-blocking alert banner is displayed: *"Repository updated since briefing was generated. [Refresh Briefing]"*.

### Prohibitions
- NEVER broadcast sync events across workspace boundaries (zero cross-tenant data leakage).
- NEVER reset user zoom/pan or re-run global Cytoscape layout upon incremental sync.
- NEVER leave SSE client connection listeners open upon unmounting components.
</must_haves>

### Task 08-03-01: Implement Workspace-Scoped Server-Sent Events Route in Gateway (Wave 3)

<task id="08-03-01" type="tracer">
<read_first>
- apps/gateway/src/middleware/tenant-auth.ts
- apps/gateway/src/app.ts
- .planning/phases/08-webhook-receiver-incremental-sync-engine/08-CONTEXT.md (D-13, D-14)
</read_first>
<action>
1. Create `apps/gateway/src/services/event-broadcaster.ts`:
   - Class `EventBroadcaster`:
     - Maintains `Map<string, Set<(event: string, data: any) => void>>` (workspaceId -> client listeners).
     - Method `subscribe(workspaceId: string, listener: Function): () => void` (returns unsubscribe function).
     - Method `broadcast(workspaceId: string, event: string, data: any): void`.
   - Export singleton `eventBroadcaster = new EventBroadcaster()`.
2. Create `apps/gateway/src/routes/events.ts`:
   - Mount tenant authorization middleware (`verifyTenantAccess`).
   - `GET /api/v1/workspaces/:workspaceId/events`:
     - Sets headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`.
     - Subscribes to `eventBroadcaster` for `workspaceId`.
     - Sends initial `: connected\n\n`.
     - Sets up `setInterval` sending `: heartbeat\n\n` every 15 seconds.
     - On socket close/abort: unregisters listener and clears interval.
3. Update `apps/gateway/src/services/incremental-sync.ts`:
   - After completing sync, call `eventBroadcaster.broadcast(workspaceId, 'sync:complete', deltaPayload)`.
4. Mount events router in `apps/gateway/src/app.ts`.
</action>
<acceptance_criteria>
- Unauthorized requests to `/api/v1/workspaces/:workspaceId/events` are rejected with 401/403.
- Authorized clients receive `text/event-stream` with regular heartbeats.
- Broadcaster delivers `sync:complete` payload with exact updated node IDs.
- Disconnected clients are pruned from the listener map without memory leaks.
- Vitest suite in `apps/gateway/test/routes/events.test.ts` passes 100%.
</acceptance_criteria>
