# Plan 08-01: HMAC-Verified Webhook Listener & Async Ingestion Job Engine

> Implement timing-safe HMAC-SHA256 GitHub webhook authentication, delivery deduplication, event/branch filtering, and fast asynchronous job dispatch in `apps/gateway` (SYNC-01).

---

## Objective

Equip `apps/gateway` with a robust GitHub webhook receiver endpoint (`POST /api/v1/webhooks/github`). Ensure every incoming request is verified against `GITHUB_WEBHOOK_SECRET` using timing-safe HMAC-SHA256 comparison, protected against replay attacks via an in-memory LRU delivery cache, filtered to default branch pushes and merged PRs, and acknowledged with HTTP `202 Accepted` in <50ms while dispatching background graph synchronization jobs (SYNC-01).

---

## Threat Model (ASVS Level 1)

<threat_model>
| Threat ID | Category (STRIDE) | Description | Severity | Mitigation Task | Verification |
|-----------|-------------------|-------------|----------|-----------------|--------------|
| T-08-01 | Spoofing / Tampering | Attacker posts forged webhook payloads without valid HMAC signature to trigger unauthorized graph mutations | High | Task 08-01-01 | Timing-safe HMAC verification rejecting missing or invalid `X-Hub-Signature-256` with 401 Unauthorized |
| T-08-02 | Information Disclosure | Timing attacks on HMAC comparison byte comparison allow signature forgery via timing discrepancy | High | Task 08-01-01 | Use `crypto.timingSafeEqual` with fixed-length buffer comparison |
| T-08-03 | Denial of Service / Replay | Replaying captured webhook deliveries causes duplicate ingestion jobs and resource exhaustion | Medium | Task 08-01-02 | In-memory LRU cache of last 10,000 `X-GitHub-Delivery` IDs returning instant 200 `{ deduplicated: true }` |
| T-08-04 | Denial of Service | Processing heavy commit diffs synchronously in the request handler causes GitHub 10s webhook timeout | Medium | Task 08-01-03 | Immediate HTTP 202 Accepted (<50ms) with decoupled background async execution |
</threat_model>

## Must Haves

<must_haves>
### Truths
- `verifyWebhookSignature(rawBody, signature, secret)` uses `crypto.createHmac('sha256', secret)` and `crypto.timingSafeEqual` to validate `X-Hub-Signature-256`.
- Requests with missing, malformed, or mismatched HMAC signatures are rejected with HTTP `401 Unauthorized` (`{ error: 'Invalid webhook signature', code: 'INVALID_SIGNATURE' }`).
- `WebhookDeduplicator` tracks `X-GitHub-Delivery` GUIDs with a 10,000-entry LRU cache, returning `{ duplicate: true }` for re-deliveries.
- Endpoint `POST /api/v1/webhooks/github` filters for `push` events to the repository's default branch (`refs/heads/main` or `refs/heads/master`) and `pull_request` events with `action === 'closed' && pull_request.merged === true`.
- Untracked repositories (no matching workspace in FalkorDB) return HTTP `200 OK` with `{ ignored: true, reason: 'untracked_repository' }`.
- Valid targeted events return HTTP `202 Accepted` with `{ status: 'queued', deliveryId }` within 50ms, spawning an async sync task tracked by FalkorDB `(:IngestJob)`.

### Prohibitions
- NEVER use standard string comparison (`===` or `==`) for HMAC signature validation.
- NEVER block the webhook HTTP response waiting for graph mutations or external git clones.
- NEVER process pushes to non-default feature branches into the canonical workspace graph.
</must_haves>

## Tasks

### Task 08-01-01: Implement Timing-Safe HMAC-SHA256 Webhook Verification Middleware (Wave 1)

<task id="08-01-01" type="tracer">
<read_first>
- apps/gateway/src/app.ts
- apps/gateway/src/types.ts
- .planning/phases/08-webhook-receiver-incremental-sync-engine/08-CONTEXT.md (D-01)
</read_first>
<action>
Create `apps/gateway/src/middleware/webhook-auth.ts` providing:
1. `computeSignature(rawBody: string | Buffer, secret: string): string`: Computes `sha256=${crypto.createHmac('sha256', secret).update(rawBody).digest('hex')}`.
2. `timingSafeCompare(a: string, b: string): boolean`: Converts hex digests into Buffers of equal length and calls `crypto.timingSafeEqual(bufA, bufB)`. Returns `false` if lengths differ.
3. Hono middleware `webhookSignatureValidator()`:
   - Reads `X-Hub-Signature-256` header.
   - If missing, throws or returns `c.json({ error: 'Missing X-Hub-Signature-256 header', code: 'MISSING_SIGNATURE' }, 401)`.
   - Reads raw request body.
   - Computes expected signature using `process.env.GITHUB_WEBHOOK_SECRET || ''`.
   - Compares signatures with `timingSafeCompare`.
   - If invalid, returns `c.json({ error: 'Invalid webhook signature', code: 'INVALID_SIGNATURE' }, 401)`.
   - If valid, stores parsed payload and raw body on Hono context for downstream handlers and calls `next()`.
</action>
<acceptance_criteria>
- Valid HMAC-SHA256 signatures pass verification cleanly.
- Tampered payloads or wrong secret keys fail with HTTP 401 and code `INVALID_SIGNATURE`.
- Missing `X-Hub-Signature-256` header returns HTTP 401 with code `MISSING_SIGNATURE`.
- Comparison uses `crypto.timingSafeEqual` and never exposes byte-comparison timing differences.
- Unit tests in `apps/gateway/test/middleware/webhook-auth.test.ts` pass 100%.
</acceptance_criteria>

### Task 08-01-02: Implement LRU Webhook Delivery Deduplication Cache (Wave 1)

<task id="08-01-02">
<read_first>
- apps/gateway/src/types.ts
- .planning/phases/08-webhook-receiver-incremental-sync-engine/08-CONTEXT.md (D-02)
</read_first>
<action>
Create `apps/gateway/src/services/webhook-dedup.ts`:
1. Class `WebhookDeduplicator`:
   - Configurable maximum size (default: 10,000 entries).
   - In-memory `Map<string, number>` tracking `deliveryId -> timestamp`.
   - Method `isDuplicate(deliveryId: string): boolean`: Checks if `deliveryId` exists. If yes, returns `true`. If no, records entry with current timestamp and returns `false`.
   - Method `evictOldest()`: When map size exceeds maximum, deletes oldest entries (FIFO / LRU ordering).
   - Method `clear()`: For test resets.
2. Export singleton `webhookDeduplicator = new WebhookDeduplicator()`.
</action>
<acceptance_criteria>
- First check for a delivery GUID returns `false` (not a duplicate).
- Immediate second check for same delivery GUID returns `true` (duplicate detected).
- When capacity exceeds 10,000 entries, oldest entries are evicted without memory leak.
- Unit tests in `apps/gateway/test/services/webhook-dedup.test.ts` pass cleanly.
</acceptance_criteria>

### Task 08-01-03: Implement Webhook Route Handler & Async Ingest Job Dispatcher (Wave 1)

<task id="08-01-03">
<read_first>

- apps/gateway/src/services/webhook-dedup.ts
- packages/graph/src/client.ts
- .planning/phases/08-webhook-receiver-incremental-sync-engine/08-CONTEXT.md (D-03, D-04)
</read_first>
<action>
1. Create `apps/gateway/src/services/sync-orchestrator.ts`:
   - Function `createIncrementalJob(graphClient, workspaceId, event, deliveryId): Promise<string>`: Creates FalkorDB `(:IngestJob { id: uuid, workspace_id: workspaceId, type: 'incremental_sync', status: 'pending', created_at: timestamp })`.
   - Function `dispatchSync(jobId, payload)`: Stub/interface for Phase 8 Plan 02 background execution.
2. Create `apps/gateway/src/routes/webhooks.ts`:
   - Mount `webhookSignatureValidator()` middleware.
   - POST `/github`:
     - Extract `X-GitHub-Event` and `X-GitHub-Delivery`.
     - Deduplication check via `webhookDeduplicator.isDuplicate(deliveryId)`. If duplicate, return `200 OK` with `{ status: 'ok', deduplicated: true }`.
     - Event filtering:
       - If `event === 'push'`: check `payload.ref`. If not default branch (`refs/heads/${payload.repository.default_branch}`), return `200 OK` with `{ ignored: true, reason: 'non_default_branch' }`.
       - If `event === 'pull_request'`: check `payload.action === 'closed' && payload.pull_request.merged === true`. If not, return `200 OK` with `{ ignored: true, reason: 'pr_not_merged' }`.
       - All other event types: return `200 OK` with `{ ignored: true, reason: 'unsupported_event' }`.
     - Repository lookup: Query FalkorDB to verify workspace exists for repository (`MATCH (w:Workspace { github_repo: $repoFullName }) RETURN w.id AS id`).
       - If no workspace found, return `200 OK` with `{ ignored: true, reason: 'untracked_repository' }`.
     - Create IngestJob and queue background processing:
       - Call `createIncrementalJob()`.
       - Trigger background execution asynchronously without `await`.
       - Immediately return `202 Accepted` with `{ status: 'queued', deliveryId, jobId: job.id }`.
3. Mount `/api/v1/webhooks` in `apps/gateway/src/app.ts`.
</action>
<acceptance_criteria>
- Valid default branch push webhook returns HTTP 202 Accepted with job ID in <50ms.
- Feature branch push returns HTTP 200 with `{ ignored: true, reason: 'non_default_branch' }`.
- Unmerged PR returns HTTP 200 with `{ ignored: true, reason: 'pr_not_merged' }`.
- Untracked repository returns HTTP 200 with `{ ignored: true, reason: 'untracked_repository' }`.
- Duplicate delivery GUID returns HTTP 200 with `{ deduplicated: true }`.
- Integration test suite in `apps/gateway/test/routes/webhooks.test.ts` passes 100%.
</acceptance_criteria>
