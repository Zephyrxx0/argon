# Plan 08-02: Incremental Git Mutation, Rolling Co-Change & ADR Supersession Engine

> Implement openCypher atomic incremental sync queries, rolling pairwise co-change updates, PR ADR diff detection, temporal validity advancement, and in-process CPU vector embedding (SYNC-02, SYNC-03).

---

## Objective

Build the core incremental synchronization engine in `packages/graph` and `apps/gateway`. Enable the system to ingest commits, authors, file touches, and co-change coupling directly from GitHub push payloads without re-cloning git repositories, and advance ADR temporal validity windows (`valid_to`) on merged pull requests with inline 512-d vector embeddings and dual governance linking (SYNC-02, SYNC-03).

## Must Haves

<must_haves>
### Truths
- `INCREMENTAL_SYNC_COMMITS` query unwinds commits and file touches in an atomic Cypher transaction, creating `(:Person)`, `(:Commit)`, `(:File)`, `[:AUTHORED]`, and `[:TOUCHES]` edges.
- Commits matching git revert regex patterns establish directed `(:Commit)-[:REVERTS]->(:Commit)` edges.
- Removed files in a commit set `(:File { deleted: true, deleted_at: timestamp })` without removing historical node connections.
- Commits modifying $\le 50$ files update `[:CO_CHANGES_WITH]` edges between all co-touched file pairs by incrementing `count` and recalculating `weight`.
- On merged PRs with changed markdown files under ADR directories, system parses decisions with `parseAdrContent`, generates 512-d embeddings via EmbeddingGemma-2 on CPU, and links `(:Decision)-[:GOVERNS]->(:File)`.
- When an ADR supersedes an existing decision, old decision's `valid_to` advances to `pr.merged_at`, new decision's `valid_from` is set to `pr.merged_at`, and `(new:Decision)-[:SUPERSEDES]->(old:Decision)` is created.
- FalkorDB `(:IngestJob)` transitions atomically from `pending` -> `processing` -> `completed` (or `failed` with redacted error).

### Prohibitions
- NEVER trigger a full git shallow clone (`git clone`) for incremental push synchronization.
- NEVER recalculate the full global workspace co-change matrix on single-commit pushes.
- NEVER set non-monotonic temporal timestamps (e.g. `valid_to < valid_from`).
- NEVER leave newly synced ADR decision nodes without 512-d vector embeddings.
</must_haves>

### Task 08-02-01: Implement OpenCypher Incremental Sync & Rolling Coupling Queries (Wave 2)

<task id="08-02-01" type="tracer">
<read_first>

</read_first>
<action>
Create `packages/graph/src/queries/sync.ts` exporting:
1. `INCREMENTAL_SYNC_COMMITS_QUERY`:
   - Takes `$workspaceId`, `$commits` (array of `{ sha, message, authorEmail, authorName, timestamp, added: string[], modified: string[], removed: string[], revertsSha?: string }`).
   - UNWINDS `$commits AS c`:
     - `MERGE (w:Workspace { id: $workspaceId })`
     - `MERGE (p:Person { email: c.authorEmail, name: c.authorName })`
     - `MERGE (cm:Commit { id: c.sha }) SET cm.message = c.message, cm.timestamp = c.timestamp, cm.workspace_id = $workspaceId`
     - `MERGE (p)-[:AUTHORED]->(cm)`
     - `MERGE (cm)-[:IN_WORKSPACE]->(w)`
     - For touched files (`c.added + c.modified`): `MERGE (f:File { path: path, workspace_id: $workspaceId }) MERGE (cm)-[:TOUCHES { change_type: 'modified' }]->(f)`
     - For removed files (`c.removed`): `MERGE (rf:File { path: path, workspace_id: $workspaceId }) SET rf.deleted = true, rf.deleted_at = c.timestamp MERGE (cm)-[:TOUCHES { change_type: 'deleted' }]->(rf)`
     - For revert commits where `c.revertsSha` is present: `MATCH (target:Commit { id: c.revertsSha, workspace_id: $workspaceId }) MERGE (cm)-[:REVERTS]->(target)`
2. `UPDATE_ROLLING_COUPLING_QUERY`:
   - Takes `$workspaceId`, `$pairs` (array of `{ fileA, fileB }`).
   - UNWINDS `$pairs AS pair`:
     - `MATCH (f1:File { path: pair.fileA, workspace_id: $workspaceId })`
     - `MATCH (f2:File { path: pair.fileB, workspace_id: $workspaceId })`
     - `MERGE (f1)-[r:CO_CHANGES_WITH]-(f2) ON CREATE SET r.count = 1, r.weight = 0.1 ON MATCH SET r.count = r.count + 1, r.weight = round((r.count * 1.0) / (r.count + 5) * 100) / 100`
3. `ADVANCE_ADR_SUPERSEDED_QUERY`:
   - Takes `$workspaceId`, `$oldDecisionId`, `$newDecisionId`, `$mergedAt`.
   - `MATCH (old:Decision { id: $oldDecisionId, workspace_id: $workspaceId }) SET old.valid_to = $mergedAt, old.status = 'superseded'`
   - `MATCH (new:Decision { id: $newDecisionId, workspace_id: $workspaceId }) SET new.valid_from = $mergedAt`
   - `MERGE (new)-[:SUPERSEDES]->(old)`
4. `UPSERT_DECISION_QUERY`:
   - Merges `(:Decision { id: $id, workspace_id: $workspaceId })` with properties (`title`, `problem`, `decision`, `status`, `valid_from`, `valid_to`, `embedding`), and merges `[:GOVERNS]` edges to touched `$files`.
5. Re-export all sync queries in `packages/graph/src/index.ts`.
</action>
<acceptance_criteria>
- Parameterized queries compile with TypeScript without errors.
- Unwinding commit arrays in FalkorDB creates expected `:Person`, `:Commit`, `:File`, and `:TOUCHES` nodes.
- Revert commits properly link `:Commit-[:REVERTS]->:Commit`.
- Removed files acquire `deleted: true` property while preserving historical `:TOUCHES`.
- Superseded decisions acquire updated `valid_to` and `[:SUPERSEDES]` relationship.
- Unit tests in `packages/graph/test/queries/sync.test.ts` pass cleanly.
</acceptance_criteria>

<action>
Extend `IncrementalSyncService` in `apps/gateway/src/services/incremental-sync.ts`:
1. Method `processPullRequestSync(payload)`:
   - Verifies `payload.action === 'closed' && payload.pull_request.merged === true`.
   - Obtains authenticated Octokit instance for the repository installation via `githubAppService.getInstallationOctokit(installationId)`.
   - Calls `octokit.rest.pulls.listFiles({ owner, repo, pull_number })` to retrieve list of changed files.
   - Filters for files matching ADR regex patterns (`^docs/adr/.*\.md$`, `^docs/decisions/.*\.md$`, `^decisions/.*\.md$`, `.*\.adr\.md$`).
   - If ADR files were added or modified:
     - For each ADR file, fetches raw markdown content via `octokit.rest.repos.getContent({ owner, repo, path, ref: payload.pull_request.merge_commit_sha })`.
     - Parses structured decision data using `parseAdrContent()` from `packages/ingest/src/mining/adr.ts`.
     - Generates 512-d vector embedding using `generateEmbedding()` from `packages/graph/src/embedding/embedder.ts`.
     - Determines governed files: uses explicit file references parsed from ADR markdown; if none, defaults to all code files modified in the pull request.
     - Inserts/updates `(:Decision)` node using `UPSERT_DECISION_QUERY`.
     - If the ADR supersedes an existing decision (e.g. `supersedes: ADR-0004`):
       - Identifies target decision in FalkorDB.
       - Advances temporal window using `ADVANCE_ADR_SUPERSEDED_QUERY`, setting old `valid_to = payload.pull_request.merged_at`, new `valid_from = payload.pull_request.merged_at`, and creating `[:SUPERSEDES]`.
2. Connect `syncOrchestrator.dispatchSync()` for `pull_request` events.
</action>
<acceptance_criteria>
- Merged PRs with ADR changes fetch file contents and parse decision metadata.
- Embeddings are generated inline in ~150ms using EmbeddingGemma-2 on Node.js CPU.
- Superseded decisions have `valid_to` updated to `pr.merged_at` and `[:SUPERSEDES]` edge created.
- Decisions are linked to explicitly mentioned files, or all PR files as fallback.
- Merged PRs without ADR changes complete cleanly with zero errors.
- Vitest tests in `apps/gateway/test/services/incremental-sync.test.ts` pass 100%.
