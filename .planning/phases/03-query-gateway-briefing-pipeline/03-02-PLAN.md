### ASVS Level 1 Controls & Threat Mitigations

| Threat ID | Threat Description | ASVS Control | Mitigation in this Plan |
|---|---|---|---|
| **T-03-06** | Excessive Data Exposure & Context Overflow: Large repositories return hundreds of files/components, exceeding downstream model context limits or bloating memory. | **ASVS V13.1.3** (Verify data bounding on external responses) | The parallel dispatcher strictly truncates retrieved entities to hard caps before prompt assembly: max 15 touched files, max 5 blast-radius components, top 5 owners/reviewers, top 5 constraining decisions, top 3 precedent decisions per D-08. |
| **T-03-07** | Path Traversal / Injection in Scope Extraction: Malicious user inputs with directory traversal tokens (`../../etc/passwd`) or arbitrary characters distort graph matching. | **ASVS V5.1.4 / V12.3.1** (Input sanitization and canonical path resolution) | Regex heuristics strictly validate and normalize extracted file paths and component tokens, stripping leading relative traversals (`../`) before forwarding to `resolveScope` per D-05. |
| **T-03-08** | Ungrounded Execution on Missing Data / Hallucination Trigger: Running an LLM on empty or irrelevant retrieval prompts causes model hallucination. | **ASVS V5.1.2** (Fail-safe defaults and data integrity) | If parallel retrieval returns 0 files, 0 components, and 0 decisions, the dispatcher triggers an immediate short-circuit returning `status: "NO_GRAPH_DATA"`, bypassing LLM invocation entirely per D-12. |
</threat_model>
