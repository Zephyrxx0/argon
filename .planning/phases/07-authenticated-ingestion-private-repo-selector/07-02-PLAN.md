# Plan 07-02: GitHub App Service & User Identity Linking

> Implement backend GitHub App installation token generation with TTL cache, repository listing endpoints, and openCypher identity linking `(:User)-[:IDENTIFIES]->(:Person)`.

---

## Objective

Build the backend GitHub App service in `apps/gateway` to securely mint installation tokens and query authorized repositories, and extend `packages/ingest` writer to link authenticated `(:User)` accounts to mined `(:Person)` git commit author nodes in FalkorDB (ING-04, TENANT-02).

---

## Threat Model (ASVS Level 1)

<threat_model>
| Threat ID | Category (STRIDE) | Description | Severity | Mitigation Task | Verification |
|-----------|-------------------|-------------|----------|-----------------|--------------|
| T-07-04 | Elevation of Privilege | An authenticated user requests a clone token or repository list for an installation they do not own or belong to | High | Task 07-02-02 | Dual verification check asserts user's GitHub identity is an authorized member of installation |
| T-07-05 | Information Disclosure / DoS | Excessive GitHub App token requests trigger GitHub API rate limiting | Medium | Task 07-02-01 | In-memory TTL cache with 5-minute pre-expiry buffer reduces external JWT exchanges |
| T-07-06 | Tampering / Cross-Tenant Graph Corruption | Mismatched author linking maps commits to the wrong user account | High | Task 07-02-03 | Strict multi-factor criteria (verified email list, noreply pattern matching, exact case-insensitive login) |
</threat_model>

---

## Must Haves

<must_haves>
### Truths
- `GitHubAppService` mints short-lived installation tokens using `@octokit/auth-app` and caches them in-memory keyed by `installationId` for up to 55 minutes.
- `GET /api/v1/github/repositories` returns authorized repository metadata for the authenticated user's installations.
- `POST /api/v1/workspaces/ingest` performs dual authorization verification before initiating private repository ingestion.
- `linkUserToMinedPersons()` creates explicit `(:User)-[:IDENTIFIES]->(:Person)` edges in FalkorDB using multi-factor identity matching.
- Identity linking runs both at the completion of repository ingestion and upon user authentication.

### Prohibitions
- NEVER expose GitHub App private key credentials outside of `apps/gateway`.
- NEVER issue an installation token to a user who is not an authorized collaborator of the installation.
- NEVER delete or overwrite mined git author records (`:Person`) during identity linking; only create `[:IDENTIFIES]` edges.
</must_haves>

### Task 07-02-01: Implement GitHubAppService with In-Memory TTL Token Cache (Wave 1)

<task id="07-02-01" type="tracer">

- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-CONTEXT.md (D-01, D-02)
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-RESEARCH.md
</read_first>
<action>
1. Add `@octokit/auth-app` (`^8.3.1`) and `@octokit/rest` (`^22.0.1`) to `apps/gateway/package.json` dependencies. Run `pnpm install` in workspace root.
2. Create `apps/gateway/src/services/github-app.ts`:
   - Define interface `CachedToken { token: string; expiresAt: number }`.
   - Implement `GitHubAppService` class:
     - Constructor accepts optional config (`appId`, `privateKey`, `clientId`, `clientSecret`), falling back to `process.env`.
     - Maintains in-memory `Map<number, CachedToken>` cache.
     - `getInstallationToken(installationId: number): Promise<string>`:
       - Checks cache. If exists and `Date.now() < cached.expiresAt - 5 * 60 * 1000` (5-minute safety buffer), returns cached token.
       - Otherwise, calls `@octokit/auth-app` `createAppAuth` to obtain installation token.
       - Parses `expiresAt` ISO string, stores in cache, returns token.
     - `getUserInstallations(userAccessToken: string)`:
       - Lists installations accessible to the user using Octokit.
     - `getInstallationRepositories(installationId: number)`:
       - Uses installation token to query `GET /installation/repositories`, returning repository objects with `id`, `name`, `full_name`, `private`, `default_branch`, `owner` (login, avatar_url), `description`, `html_url`.
3. Create unit tests in `apps/gateway/test/services/github-app.test.ts` testing cache hits, cache expiration, and token acquisition with mock Octokit auth.
</action>
<acceptance_criteria>
- `GitHubAppService` generates installation tokens and caches them by `installationId`.
- Consecutive calls within 50 minutes return the cached token without re-authenticating.
- Expired cache entries trigger a fresh token request.
- `apps/gateway/test/services/github-app.test.ts` passes.
</acceptance_criteria>

</read_first>
<action>
1. Create `apps/gateway/src/routes/github.ts`:
   - Initialize Hono router mounting routes under `/api/v1/github`:
   - Route `GET /repositories`:
     - Apply JWT authentication middleware (`tenantAuth()`).
     - Rejects unauthenticated requests with `401 Unauthorized`.
     - Queries `GitHubAppService` for repositories accessible across the user's installations.
     - Returns JSON `{ repositories: GitHubRepositoryItem[] }`.
   - Route `POST /ingest`:
     - Apply JWT authentication middleware (`tenantAuth()`).
     - Accepts request body `{ repositoryFullName: string, installationId: number }`.
     - Dual verification: checks that `installationId` is associated with the user's authorized account before proceeding. If unauthorized, returns `403 Forbidden`.
     - Obtains short-lived token via `githubAppService.getInstallationToken(installationId)`.
     - Dispatches ingestion pipeline with `installationToken` in memory.
     - Creates workspace record in FalkorDB with `(:User)-[:OWNS]->(:Workspace)` and `(:User)-[:ACCESSES]->(:Workspace)`.
2. Register `github.ts` routes in `apps/gateway/src/app.ts`.
3. Create tests in `apps/gateway/test/routes/github-repos.test.ts` verifying authentication guard, repository serialization, and dual verification 403 refusal.
</action>

### Task 07-02-03: Implement openCypher Identity Linking `(:User)-[:IDENTIFIES]->(:Person)` (Wave 2)

<task id="07-02-03">
<read_first>
- packages/ingest/src/writer/queries.ts
- packages/ingest/src/writer/falkordb.ts
- packages/ingest/src/pipeline.ts
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-CONTEXT.md (D-13, D-14, D-15)
</read_first>
<action>
1. In `packages/ingest/src/writer/queries.ts`:
   - Add openCypher query `LINK_USER_TO_PERSONS_QUERY`:
     ```cypher
     MATCH (u:User {id: $userId})
     MATCH (p:Person)
     WHERE (p.email IS NOT NULL AND p.email IN $userEmails)
        OR p.email ENDS WITH ('+' + u.login + '@users.noreply.github.com')
        OR p.email = (u.login + '@users.noreply.github.com')
        OR toLower(p.name) = toLower(u.login)
     MERGE (u)-[r:IDENTIFIES]->(p)
     ON CREATE SET r.created_at = timestamp()
     RETURN count(r) AS linked_count
     ```
   - Add query to retrieve linked contributor profiles with user metadata (login, avatar_url, github_id).
2. In `packages/ingest/src/writer/falkordb.ts`:
   - Export function `linkUserToMinedPersons(graphClient, userId, userLogin, userEmails: string[])`.
   - Update `runIngestionPipeline()` to invoke `linkUserToMinedPersons` at the end of the pipeline if user identity is provided in config (`userId`, `userLogin`, `userEmails`).
3. Create tests in `packages/ingest/test/writer/identity-linking.test.ts` verifying:
   - Git author matching by primary email connects via `[:IDENTIFIES]`.
   - Git author matching by noreply email connects via `[:IDENTIFIES]`.
   - Git author matching by GitHub login connects via `[:IDENTIFIES]`.
   - Unmatched authors remain unlinked without error.
</action>
