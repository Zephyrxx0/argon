# Plan 07-03: Private Repository Selector & Contributor Identity UI

> Implement the searchable GitHub repository picker in `IngestModal` and contributor identity attribution with verified badges and `[YOU]` indicators in `NodeInspector` and `ContributorPicker`.

---

## Objective

Deliver the frontend user experience for Phase 7: an accessible tabbed repository selector in `IngestModal` allowing users to filter and index authorized private repositories without typing URLs, and visual identity badges linking authenticated developers to git commit author nodes (ING-04, TENANT-02).

---

## Threat Model (ASVS Level 1)

<threat_model>
| Threat ID | Category (STRIDE) | Description | Severity | Mitigation Task | Verification |
|-----------|-------------------|-------------|----------|-----------------|--------------|
| T-07-07 | Spoofing / Impersonation | A user spoofing another contributor's identity in the UI | High | Task 07-03-02 | `[YOU]` badge is strictly conditioned on authenticated session `user.id === person.user_id` verified via JWT |
| T-07-08 | Information Disclosure (XSS) | Malicious repository names or git author metadata execute script in modal or canvas | Medium | Task 07-03-01 & Task 07-03-02 | React text rendering with strict escaping and sanitization of git metadata |
| T-07-09 | SSRF | Malicious repository URL submitted via Public URL tab targeting internal services | High | Task 07-03-01 | Retain and strengthen `validateGitUrl` blocking loopback, link-local, and private subnets |
</threat_model>

## Must Haves

<must_haves>
### Truths
- `IngestModal` renders accessible Radix tabs: "Your Repositories" and "Public Git URL".
- "Your Repositories" tab lists authorized repositories with organization avatar, private lock icon, default branch badge, and "Index Repo" CTA button.
- Repository picker includes client-side fuzzy search with 150ms debounce and organization filter pills.
- Anonymous guests viewing "Your Repositories" see a contextual empty state with a "Sign in with GitHub" button opening `AuthModal`.
- Authenticated users with 0 repositories see an empty state with an "Install GitHub App" link and a "Check Again" button.
- `NodeInspector` displays a "Verified GitHub Profile" badge and link to `github.com/<login>` on linked `(:Person)` nodes, plus a prominent cyan `[YOU]` pill when matching the current user.
- `ContributorPicker` displays linked GitHub avatars and `[YOU]` badges for the active user.

### Backstops
- { statement: "Extremely long repository names truncate with ellipsis in the middle, displaying full path on mouse hover tooltip", verification: backstop }
- { statement: "Extended sanitized error descriptions wrapped in scrollable monospace box with break-words", verification: backstop }

### Prohibitions
- NEVER render `[YOU]` pill for unauthenticated guest sessions or mismatched user IDs.
- NEVER allow repository index submission without valid installation token or valid public URL.
- NEVER freeze or block the Cytoscape canvas during background repository fetching or ingestion.
</must_haves>

## Tasks

### Task 07-03-01: Implement Tabbed IngestModal & RepoPicker Component (Wave 3)

<task id="07-03-01" type="tracer">
<read_first>
- apps/web/components/workspace/ingest-modal.tsx
- apps/web/app/globals.css
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-CONTEXT.md (D-09, D-10, D-11, D-12)
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-UI-SPEC.md (Spacing, Typography, Color, Copywriting)
</read_first>
<action>
1. Add `@radix-ui/react-tabs` (`^1.1.3`) to `apps/web/package.json` dependencies if needed and run `pnpm install`.
2. Create `apps/web/components/workspace/repo-picker.tsx`:
   - Accepts props: `onSelectRepo: (repo: GitHubRepositoryItem) => void`, `isGuest: boolean`, `onOpenAuth: () => void`.
   - Fetches repository list from Gateway `/api/v1/github/repositories` using Better Auth bearer token.
   - Implements search input with 150ms debounce filtering over `full_name`, `name`, `owner.login`.
   - Implements organization filter pills (`All` + unique owner logins) with repository counts.
   - Renders repository rows with:
     - 24x24px organization avatar (with 2-letter fallback monogram)
     - `owner/repo` title and default branch badge (`main`/`master`)
     - Visibility badge: Private (amber Lock icon) or Public (cyan Globe icon)
     - Primary button: "Index Repo" (`bg-primary text-primary-foreground hover:opacity-90 font-mono text-xs font-bold`)
   - Empty & Error states per `07-UI-SPEC.md`:
     - If `isGuest`: displays heading "Sign In to Access Private Repositories", body copy, and "Sign in with GitHub" CTA calling `onOpenAuth()`.
     - If authenticated but 0 repos: displays "No Repositories Found", link to GitHub App installation, and "Check Again" button.
     - Loading: 4 pulsing skeleton rows (`h-14 bg-muted/40 animate-pulse rounded`).
3. In `apps/web/components/workspace/ingest-modal.tsx`:
   - Replace single-form view with Radix Tabs:
     - Tab 1: `Your Repositories` (renders `RepoPicker`)
     - Tab 2: `Public Git URL` (renders existing URL input with SSRF validation)
   - When user clicks "Index Repo" in `RepoPicker`:
     - Transitions to simulated/live multi-step progress UI (`CLONING` -> `DERIVING` -> `EMBEDDING` -> `READY`).
     - Calls Gateway `POST /api/v1/workspaces/ingest` with `repositoryFullName` and `installationId`.
     - On completion, calls `onIngestComplete(workspace)` and closes modal.
4. Create component tests in `apps/web/tests/components/ingest-modal-picker.test.tsx` verifying tabs switching, search filtering, empty states, and index triggering.
</action>
<acceptance_criteria>
- `IngestModal` renders tabs for "Your Repositories" and "Public Git URL".
- Repositories can be searched by name and filtered by organization pill.
- Guest mode shows "Sign In with GitHub" prompt.
- Clicking "Index Repo" initiates the ingestion workflow.
- `apps/web/tests/components/ingest-modal-picker.test.tsx` passes.
</acceptance_criteria>

### Task 07-03-02: Implement Contributor Identity Attribution in Canvas & Pickers (Wave 3)

<task id="07-03-02">
<read_first>
- apps/web/components/contributor/contributor-picker.tsx
- apps/web/components/canvas/node-inspector.tsx
- apps/web/lib/auth-client.ts
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-CONTEXT.md (D-16)
- .planning/phases/07-authenticated-ingestion-private-repo-selector/07-UI-SPEC.md
</read_first>
<action>
1. In `apps/web/components/contributor/contributor-picker.tsx`:
   - Consume active session via `useSession()` from `@/lib/auth-client`.
   - Update contributor dropdown list item rendering:
     - If contributor has linked user data (avatar, login): render avatar image next to contributor name.
     - If contributor's linked user ID equals `session?.user?.id` (or login matches): render cyan pill badge `[YOU]` (`bg-primary/20 text-primary border border-primary/40 font-mono text-[10px] font-bold px-1.5 py-0.5 rounded`).
2. In `apps/web/components/canvas/node-inspector.tsx`:
   - When inspecting a node with `data.type === 'Person'`:
     - Check if person node has linked user metadata (`github_login`, `avatar_url`, `user_id`).
     - If linked:
       - Render GitHub profile avatar.
       - Display verified badge with `ShieldCheck` icon: "Verified GitHub Profile".
       - Render external link button to `https://github.com/${data.github_login}`.
       - If `data.user_id === session?.user?.id`: render prominent `[YOU]` badge next to name.
     - If unlinked: render standard contributor view without verified badge.
3. Create component tests in `apps/web/tests/components/contributor-identity.test.tsx` verifying:
   - Contributor matching active user renders `[YOU]` badge.
   - Contributor not matching active user does not render `[YOU]` badge.
   - Node inspector renders verified badge and profile link for linked author nodes.
</action>
<acceptance_criteria>
- `[YOU]` badge renders on `ContributorPicker` and `NodeInspector` when user identity matches.
- Verified GitHub profile link and avatar render on linked `(:Person)` nodes.
- Unlinked git authors render cleanly without errors.
- `apps/web/tests/components/contributor-identity.test.tsx` passes.
</acceptance_criteria>
