### ASVS Level 1 Controls & Threat Mitigations

| Threat ID | Threat Description | Severity | ASVS Category | Mitigation Strategy |
|---|---|---|---|---|
| **T-06-07** | Insecure Direct Object Reference (IDOR) during guest-to-user account linking | High | V4 Access Control | Better Auth's `onLinkAccount` runs strictly in authenticated server context with trusted `anonymousUser.id` and `newUser.id` values issued by Better Auth core, preventing forged migration parameters (D-13, D-14). |
| **T-06-09** | Session fixation / orphan session persistence on logout | Medium | V3 Session Management | On logout, revoke authenticated session cookie on the server, clear all in-memory auth state, mint an entirely fresh guest UUID, and reset workspace selection (D-15). |
| **T-06-10** | Graph privilege escalation via role mutation during account migration | High | V4 Access Control | Migration Cypher query copies existing relationship properties (`SET r2.role = r.role`) and immediately detaches and deletes the temporary guest node in the same transaction, preventing role elevation or duplicate edge attacks (D-14). |
</threat_model>

<action>
1. Update `packages/graph/src/queries/auth.ts`:
   - Implement `migrateGuestAccess(client: ArgonGraphClient, params: { guestId: string; authUserId: string }): Promise<number>`:
     - Run parameterized openCypher query conforming to D-14:
       ```cypher
       MATCH (guest:User {id: $guestId})-[r:ACCESSES]->(w:Workspace)
       MERGE (u:User {id: $authUserId})
       MERGE (u)-[r2:ACCESSES]->(w)
       SET r2.role = r.role
       DETACH DELETE guest
       RETURN count(w) AS migratedCount;
       ```
     - Return the number of migrated workspace access edges.

2. Export `migrateGuestAccess` from `packages/graph/src/index.ts`.

3. Update `apps/web/lib/auth.ts`:
   - In `anonymous(...)` plugin options, define `onLinkAccount`:
     ```typescript
     onLinkAccount: async ({ anonymousUser, newUser }) => {
       try {
         const { ArgonGraphClient, migrateGuestAccess } = await import('@argon/graph');
         const graphClient = new ArgonGraphClient();
         await graphClient.connect();
         await migrateGuestAccess(graphClient, {
           guestId: anonymousUser.id,
           authUserId: newUser.id,
         });
         await graphClient.close();
       } catch (err) {
         console.error('[auth:onLinkAccount] Failed to migrate guest graph accesses:', err);
       }
     }
     ```

4. Create `apps/web/tests/auth/account-linking.test.ts`:
   - Test that calling `migrateGuestAccess` transfers temporary `[:ACCESSES]` relationships from `guest_123` to authenticated `user_456`.
   - Verify temporary `(:User {id: 'guest_123'})` node is deleted after migration.
   - Verify `onLinkAccount` callback successfully invokes migration logic without unhandled errors.
</action>
