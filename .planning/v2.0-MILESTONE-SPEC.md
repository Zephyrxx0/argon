# Milestone v2.0 Specification: GitHub App Integration & Incremental Sync

**Status:** Draft / Ready for Milestone Planning  
**Target Milestone:** `v2.0`  
**Previous Shipped Milestone:** `v1.0 MVP` (Tagged `v1.0`)

---

## 1. Objective

Upgrade Argon from a guest-first public repository explorer into an authenticated, production-grade project-memory system capable of securely indexing **private repositories**, enforcing **multi-tenant graph access control**, and **incrementally syncing** graph nodes on push and pull-request webhook events.

---

## 2. Requirements & Capabilities

### Core Requirements
- **AUTH-01 (GitHub App Integration & Session Management):**
  - Implement GitHub App authentication via Auth.js / NextAuth v5 in `apps/web`.
  - Secure HTTP-only JWT sessions storing user identity (`github_id`, `login`, avatar).
  - Exchange user access tokens / installation IDs for short-lived (1-hour) GitHub API tokens.
  - HeaderBar avatar, profile popover, and sign-in/sign-out triggers.

- **AUTH-02 (Multi-Tenant Graph Authorization):**
  - Update FalkorDB openCypher schema with `(:User)` and `(:Organization)` node labels.
  - Establish `(:User)-[:ACCESSES]->(:Workspace)` and `(:User)-[:OWNS]->(:Workspace)` edges.
  - Update `apps/gateway` to verify that the requesting user has an `[:ACCESSES]` edge to `:workspaceId` before executing any named query.
  - Prevent cross-tenant data leakage and information disclosure.

- **ING-04 (Authenticated Ingestion & Token Redaction):**
  - Private repository ingestion using ephemeral git clones with `x-access-token:<installation_token>@github.com`.
  - Strict secret redaction middleware in `packages/ingest` ensuring tokens never leak to git stdout/stderr, FalkorDB `(:IngestJob)` error properties, or console logs.
  - Replace manual URL typing in `IngestModal` with a searchable dropdown populated via GitHub REST API (`GET /user/installations` & `GET /installation/repositories`).

- **SYNC-01 (Webhook Listener & Incremental Graph Updates):**
  - New webhook endpoint in `apps/gateway` (`POST /api/v1/webhooks/github`) verifying GitHub HMAC-SHA256 payload signatures (`X-Hub-Signature-256`).
  - Process `push` events: extract changed files from commits, update `File` and `TOUCHES` nodes, update co-change coupling.
  - Process `pull_request` (closed & merged) events: extract merge commits, mine reverted PRs, extract newly committed ADRs/RFCs, and advance temporal validity windows without full re-cloning.

## 3. Proposed Phase Architecture

### Phase 06: Authentication & Multi-Tenant Authorization
- **Deliverables:**
  - `apps/web` Auth.js GitHub provider integration.
  - Session cookie handling and user identity context provider.
  - FalkorDB schema extensions (`schema.cypher` adding `User`, `Organization`, and uniqueness constraints).
  - `apps/gateway` JWT / bearer token tenant validation middleware.
- **Verification:** Unit tests for session issuance, Cypher tenant query validation, and unauthorized 403 refusal tests.

### Phase 07: Authenticated Ingestion & Private Repo Selector
- **Deliverables:**
  - Short-lived GitHub App installation token generation service.
  - `packages/ingest` authenticated shallow git clone (`x-access-token`) with regex secret scrubbing.
  - `apps/web` repository picker component querying authorized installations.
  - Automatic linking between authenticated GitHub user and mined `(:Person)` graph nodes.
- **Verification:** Mock private repo clone test, secret leak prevention test, and repo picker UI test.

### Phase 08: Webhook Receiver & Incremental Sync Engine
- **Deliverables:**
  - `apps/gateway/src/routes/webhook.ts` with timing-safe HMAC signature verification.
  - Incremental diff processor in `packages/ingest` updating changed files and touches.
  - Incremental ADR parser advancing `valid_to` timestamps on supersession.
  - Cytoscape canvas live pulse or notification when graph sync occurs.
- **Verification:** Webhook signature verification tests, incremental commit touch tests, and temporal window advancement tests.

## 5. Security & Threat Modeling (ASVS Level 1)

1. **Token Redaction in Git Shell Calls:** Git commands echoing repository URLs must have remote URLs sanitized before logging or writing to `:IngestJob.error`.
2. **Timing-Safe HMAC Webhook Verification:** `crypto.timingSafeEqual` must be used to compare `X-Hub-Signature-256` signatures to prevent timing attacks.
3. **Cross-Tenant Graph Isolation:** Any request to `POST /api/v1/:workspaceId/query/:query` MUST prove tenant ownership or membership via Cypher `MATCH (u:User {id: $userId})-[:ACCESSES]->(w:Workspace {id: $workspaceId})`.
4. **Short-Lived Installation Tokens:** User tokens are only used for OAuth login; repo access uses GitHub App installation tokens that expire automatically in 60 minutes.
